# User-manual video snippets

Short screen recordings of UI actions for the user manual, generated by Playwright so they can be
re-recorded whenever the UI changes.

```bash
make doc-snippets                                   # build frontend, record everything
make doc-snippets SNIPPETS="first-bar-chart"        # record a subset

# Without rebuilding (frontend/build must exist):
cd frontend
npm run doc-snippets -- filter-values
npm run doc-snippets -- --headed filter-values      # watch the browser
DOC_SNIPPETS_URL=http://localhost:3000 npm run doc-snippets   # use a running app
```

Each snippet writes two files to `docs/assets/snippets/`:

- `<name>.webm`: the video (VP8, 1200×750)
- `<name>.png`: the final frame, used as the poster image

By default, the recorder starts a separate backend on port `8011` (override with
`DOC_SNIPPETS_PORT`). That backend serves `frontend/build` and uses an empty, temporary snapshot
store, so recordings never see your own data. Every snippet runs in a fresh browser context, which
means it gets a new session.

## Embedding in the manual

The site uses directory URLs, so `docs/getting-started/first-chart.md` is served from
`/getting-started/first-chart/`. The path in the HTML must therefore go up two levels:

```html
<video src="../../assets/snippets/first-bar-chart.webm" poster="../../assets/snippets/first-bar-chart.png"
       controls loop muted playsinline width="100%"></video>
```

Add `autoplay` to make a snippet play like a GIF. Use it sparingly, because several looping
videos on one page are distracting.

## Writing a snippet

Add `snippets/<name>.js`:

```js
module.exports = {
  // Not recorded: get the app into the starting state quickly.
  async setup(d) {
    await d.app.connectFile();                     // data/servers.csv by default
    await d.app.place('Role', d.app.shelf('x'));   // instant drag
  },
  // Recorded: human-paced actions.
  async record(d) {
    await d.drag(d.app.field('Requests (sum)'), d.app.shelf('y'));
    await d.app.waitForChart();
  },
};
```

`d` is a `Director` (see [director.js](director.js)). Use its actions rather than raw Playwright
calls. Each action moves the cursor along an eased path and pauses afterwards, so a viewer can
follow it:

| Action | Purpose |
|---|---|
| `d.click(locator)` | glide to an element and click it |
| `d.rightClick(locator)` | open a context menu, e.g. a field menu; then use `d.click(d.app.menuItem('Continuous'))` |
| `d.drag(source, target, { targetPosition })` | HTML5 drag-and-drop, with a ghost of the dragged element; `targetPosition: {x, y}` picks the drop point, e.g. the start of a shelf to insert before its chips |
| `d.setSlider(thumb, value)` | drag an MUI slider thumb (`role="slider"`) to a value, e.g. `d.setSlider(d.app.sizeSliderThumb(), 2)` |
| `d.type(locator, text)` | click, then type with a per-key delay |
| `d.press(key)` | keyboard shortcut |
| `d.chooseFiles(input, names)` | click a file input and answer the chooser with files from `data/` |
| `d.moveTo(locator)` / `d.moveToPoint(x, y)` | point at something |
| `d.caption(text)` | caption bar at the bottom of the frame |
| `d.pause(ms)` | let a result settle |

`d.app` holds app-specific locators (`field`, `shelf`, `shelfField`, `menuItem`, `filtersShelf`,
`colorShelf`, `sizeShelf`, `sizeButton`, `sizeSliderThumb`, `sectionHeader`, `filterValue`, ...) and
setup flows (`connectFile`, `place`, `setFieldType`, `buildScatter`, `setDotSize`, `closePopover`,
`waitForChart`, `restCursor`, `setMiddlePanelWidth`). `connectFile` also widens the middle panel to 280 px,
because at the default width chips in filter cards and on the Color shelf shrink to their icon. Keep all selectors in `AppSteps`, so a UI change only needs fixing in one place.
Several of them match CSS-module class prefixes (for example `DropZone_dropZone`), so renaming
one of those classes breaks the recorder.

Finish with the cursor away from buttons (`d.app.restCursor()`); otherwise a hover tooltip ends up
frozen in the poster image.

## How it looks the way it does

- **Cursor, clicks, drag ghost.** Headless screenshots contain no mouse pointer and no native drag
  image. [overlay.js](overlay.js) is injected into every page and draws an arrow that follows
  `mousemove`/`dragover`, a ripple on each press, and a copy of the dragged element. All of these
  use `pointer-events: none`, so they never affect what the app receives.
- **Trimming.** The recording uses `page.screencast.start()`/`stop()` (Playwright ≥ 1.62) around
  `record()` only, so setup and page loads never show up in the video.
- **Demo data.** `data/servers.csv` is synthetic, hourly monitoring data for 24 servers over one
  week (4,032 rows). It is generated from a fixed seed by
  [data/generate-servers.js](data/generate-servers.js), so every run produces the same file.
  Edit and re-run the generator rather than editing the CSV by hand. Add more files to `data/`
  when a snippet needs them.

  | Columns | Kind |
  |---|---|
  | `Timestamp` | datetime (discrete by default; switch to timeline mode for a time axis) |
  | `Host`, `Role` (web, api, database, cache, batch), `Environment` (production, staging), `Datacenter` (eu-west, us-east), `OS` | dimensions |
  | `Requests`, `Errors`, `Network Out (GB)` | additive measures; the default sum is meaningful |
  | `CPU (%)`, `Memory (%)`, `Disk Used (%)` | gauges; switch the aggregation to average or max, because a sum is meaningless |

  Patterns built into the data, for snippets that need something to find:
  - a daily traffic cycle peaking mid-afternoon, with a quieter weekend
  - batch servers busy at 01:00–05:00
  - the `db-02` disk filling from 58% to about 92% over the week
  - an error burst on `web-05` on Thursday from 10:00 to 13:00
  - staging carrying about 5% of production traffic

## Checking a recording without a video player

Playwright ships an ffmpeg build that can decode its own videos:

```bash
FF=$(ls ~/.cache/ms-playwright/ffmpeg-*/ffmpeg-linux | tail -1)
$FF -i docs/assets/snippets/first-bar-chart.webm -r 2 /tmp/frame-%02d.png
```
